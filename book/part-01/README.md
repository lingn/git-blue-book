# 第一篇：版本历史解决什么问题

这一篇不要求你预先知道任何 Git 命令。我们先把版本控制的工程问题说清楚，再建立贯穿全书的第一个工作模型。后续章节会把这里的直觉分别落到对象、引用、工作区、远程和平台控制面。

## 本篇内容

1. [没有版本控制时，我们到底在怕什么](01-versioned-engineering.md)
2. [从本地版本、集中式到分布式：仓库权威在哪里](02-centralized-and-distributed.md)
3. [Git 的诞生：在大规模协作中同时追求速度和可验证性](03-git-design-constraints.md)
4. [Git 保存的是快照：完整视图和差异显示是两件事](04-snapshots-and-diffs.md)
5. [一次提交在仓库里怎样组成](05-first-repository-map.md)
6. [综合场景：三种版本管理方案怎么选](exercise.md)

完成这一篇以后，你应该能用普通语言解释：为什么文件备份不等于版本控制，为什么 Git 可以在离线状态下记录历史，一次提交怎样指向完整快照，以及哪些发布、权限和运行事实不能由 Git 单独证明。

第一篇只建立选择和模型，不替第三篇重复对象格式，不替第五篇解释远程协议，也不把 Git 平台的评审与 CI 功能倒推成 Git 核心语义。
