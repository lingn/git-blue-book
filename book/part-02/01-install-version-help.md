# 安装 Git，并确认当前版本与能力边界

安装 Git 不是本章的终点。版本控制工具的行为会受客户端版本、操作系统、shell、配置来源和平台策略影响。先确认当前终端实际调用的程序，再决定是否升级，才能避免“装过了但命令仍然是旧版本”。

## 进入条件与完成标准

本章在本机终端执行，安装动作使用操作系统可信的软件来源。不要把网上复制的脚本直接以管理员权限运行，也不要在生产构建机上随意替换 Git。

读完本章后，你应能：

- 确认 Git 可执行文件、版本和帮助入口；
- 说明本书命令的最低基线和版本差异；
- 判断一个选项是客户端能力、远端能力还是平台功能；
- 发现多版本 Git、PATH、shell 和配置导致的行为差异；
- 在升级前后记录证据，不破坏现有仓库和凭据；
- 为实验准备隔离目录、合成身份和必要依赖。

## 先确认实际调用的 Git

在普通终端执行：

~~~bash
git --version
command -v git
git version --build-options
~~~

第一条显示 Git 版本。第二条显示当前 shell 找到的可执行文件路径，Windows 可使用系统对应的命令查询工具。第三条在支持的版本中显示构建和平台信息，旧版本可能不支持，失败时保留输出即可。

示例输出中的版本、路径和编译选项会因机器不同而变化。不要把“安装程序显示的版本”当成终端实际运行的版本。图形客户端也可能自带另一份 Git。

如果 Git 不存在，终端通常会提示找不到命令。此时：

- macOS 使用系统的 Command Line Tools 或你已信任的软件包管理器；
- Windows 使用 Git for Windows 官方安装来源；
- Linux 使用发行版的软件包管理器和安全更新渠道。

安装完成后重新打开终端，再重复版本和路径检查。不要为了切换版本直接删除旧可执行文件；先确认哪些 IDE、脚本和 CI 依赖它。

## 本书的版本基线

本书基础命令以 Git 2.28 及以上为主要基线，但不是所有章节都只需要这一版本。不同功能有自己的最低版本、后端和环境约束：

| 能力 | 可能受影响的因素 | 验证方式 |
| --- | --- | --- |
| init 指定初始分支 | Git 版本和初始化配置 | git init -h、实际临时仓库 |
| switch/restore | Git 版本和命令实现 | git switch -h、git restore -h |
| status porcelain v2 | Git 版本和脚本解析 | git status --porcelain=v2 |
| rebase-merges、range-diff | Git 版本和历史形状 | 命令帮助、隔离提交图 |
| AUTO_MERGE、ort 行为 | Git 版本和 merge 策略 | git version、冲突实验 |
| commit-graph、MIDX、maintenance | Git 版本、对象库和任务配置 | 命令帮助、维护后不变量 |
| SHA-256 仓库 | 初始化格式和互操作能力 | 临时仓库、目标协议文档 |
| SSH/HTTPS、LFS、平台规则 | 外部软件、服务器和权限 | 目标环境专项核对 |

遇到命令选项不存在时，先确认版本和帮助，不要把缺选项当成仓库损坏。正文中的高级能力会注明版本边界和本地实验不能覆盖的部分。

## 查看帮助而不改变项目

~~~bash
git help
git --help
git status -h
git help --no-man-viewer status
~~~

不同系统的 help 可能打开 man、浏览器或内置文本。-h 通常打印简短用法并退出，适合检查选项是否存在。完整手册的输出和分页器不应被脚本当作稳定协议。

如果 help 失败，先查看 Git 路径和安装包，不要修改仓库配置。命令帮助属于客户端事实，不证明远端平台支持相同选项。

## 多版本和 PATH 问题

图形客户端里能用而终端找不到 Git，通常是两套环境的 PATH 不同。先记录：

~~~bash
command -v git
git --version
printf '%s\n' "$PATH"
~~~

PATH 可能包含多个 Git 目录。不要在不了解 shell 初始化文件的情况下全局替换 PATH，也不要删除团队工具链。切换版本后，对本书实验和项目脚本分别运行版本检查。

IDE、预提交 hook、CI runner 和容器可能调用自己的 Git。生产问题需要记录执行主体、容器镜像、Git 版本和工作树路径，不能只引用开发机版本。

## 设置实验身份和临时环境

本书实验应该使用临时目录和合成身份：

~~~bash
lab_dir="$(mktemp -d)"
git -C "$lab_dir" init --initial-branch=main
git -C "$lab_dir" config user.name "Git Blue Book Lab"
git -C "$lab_dir" config user.email "lab@example.invalid"
git -C "$lab_dir" var GIT_AUTHOR_IDENT
~~~

实验不会修改全局身份，不读取真实令牌，也不连接远程。临时目录退出时按脚本的 cleanup 规则删除；如果需要保留现场，先把路径写入记录，确认它不含敏感内容。

不要把本机的 ~/.gitconfig、SSH key、credential helper 或真实邮箱复制进实验。配置来源和身份边界在第二篇说明。

## 安装和升级的安全边界

升级 Git 可能改变：

- 默认分支名称和初始化行为；
- merge 策略、冲突样式和 rebase 后端；
- SSH、TLS、凭据助手和签名工具调用；
- fsmonitor、untracked cache、maintenance 和性能；
- hooks、filters、safe.directory 和对象格式支持。

升级前保留当前版本、项目构建说明和回退包，先在测试仓库验证。不要把 Git 升级当成修复某个仓库状态的通用动作，也不要在事故现场先升级客户端再取证。

如果版本不满足团队基线，记录旧版本和待升级原因，使用隔离环境重跑实验。升级后重新检查项目脚本、IDE 和 CI 的实际 Git 路径。

## 常见失败和恢复

| 现象 | 先收集 | 处理 |
| --- | --- | --- |
| git: command not found | PATH、安装来源、shell | 使用可信来源安装，重新打开终端 |
| 版本与预期不同 | command -v、PATH、IDE/CI 路径 | 明确执行主体，调整环境而不是删文件 |
| 选项不存在 | git version、命令 help | 使用兼容写法或升级后在测试仓库验证 |
| help 打不开 | help.format、man/浏览器、终端 | 使用 -h 或 no-man-viewer，保留输出 |
| 初始化失败 | 目录权限、所有权、当前路径 | 换专用可写目录，不修改系统权限 |
| 升级后项目异常 | 旧版记录、Git 路径、配置来源 | 回到已验证版本或隔离复现，不覆盖仓库 |
| 实验读取真实身份 | 环境变量、global 配置、脚本 | 停止实验，清理输出并改用合成配置 |

安装问题和仓库问题要分开处理。不要为了让命令成功删除 .git、重置工作区或复制他人的配置。

## 运行本书实验

仓库根目录执行：

~~~bash
./scripts/verify-all.sh
~~~

脚本会先运行 Shell 语法检查，再在临时目录创建 Git 仓库、bare 远端、合成身份和必要 fixture。它不会验证本机 Git 的所有平台集成、真实 SSH/TLS、LFS 服务或托管平台权限。

单独运行某组实验前，先看附录实验清单的前置条件和安全边界。实验输出中的 OID、临时路径、时间和分支名都是变量，脚本应断言关系和状态，不匹配固定文本。

## 小结

先确认终端实际调用的 Git、版本和帮助，再按能力边界运行实验。Git 客户端选项、远端协议、LFS 和托管平台规则不是同一层事实。升级和安装都应在受控环境验证，实验使用合成身份和临时仓库；发现版本、PATH 或权限问题时，保留原始证据，不用破坏仓库来修复环境。
