# 第八篇：发布与 CI/CD 集成

Git 能精确标识源码对象，却不能单独证明哪个 runner 执行了什么命令、哪个制品被部署，或线上实例最终加载了什么版本。本篇把触发事件、候选提交、checkout、构建输入、制品摘要、部署记录和运行状态串成一条证据链。

本篇先使用厂商无关的 CI/CD 模型，再在需要时对照托管平台的实现。平台事件字段、检查状态、合并队列、身份令牌、制品保留和计费会随产品、版本、权限和套餐变化；正文中的平台事实必须进入 `docs/FACT-REGISTER.md` 并带核对日期。

第八篇的正文主链已经覆盖从触发、候选、构建、发布、部署、迁移到事故关闭；平台专项事实和旧页面迁移仍按总纲继续校验。未达到单章验收门槛的主题不在导航中预列占位页面。

进入本篇前，读者应理解提交对象、引用、merge-base、远程跟踪引用、浅克隆和受保护分支。读完当前章节后，应能检查 CI 实际检出的精确提交，解释路径过滤和合并队列为何会使旧结果过期，并判断哪些结论必须由平台控制面或运行环境补证。
