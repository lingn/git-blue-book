# 第十二篇：组织级运维与治理

当仓库从几十个增长到几百、几千个，问题不再只是某个开发者会不会用 Git。没人负责的仓库仍可能持有生产凭据，离职成员可能保留绕过权限，归档仓库可能继续被机器人写入，默认规则也可能因一次迁移或例外逐渐失效。

本篇把仓库视为有所有者、数据分类、依赖、权限、容量、保留期和恢复目标的工程资产。Git 负责对象与引用，托管平台负责协作控制面，身份、审计、备份和制品又属于其他系统；组织治理必须把这些状态关联起来，而不能用一条平台规则代替全生命周期管理。

进入本篇前，读者应理解受保护引用、机器身份、供应链、秘密清理、备份、迁移与灾难恢复。本篇从仓库生命周期与所有权开始，随后进入权限回收、策略例外、审计留存、容量维护和组织级演练。尚未完成的主题不以占位页进入导航。

读完本篇后，你应能为仓库建立稳定资产 ID、双重所有权、数据分类、恢复与保留契约；还原有效权限；让组织规则经过可重放求值、audit/canary 推广、窄例外和安全回退；建设能关联主体、对象、规则、时钟与采集缺口的长期审计证据系统；按完整性、可用性、时延、新鲜度、容量、治理和恢复维度管理健康；并把这些控制编排成有明确指挥权、状态门禁、停止条件、单一写入权威和行动闭环的组织级恢复演练。
