# 配置身份：提交为什么需要作者

## 提交需要回答“是谁记录的”

第一篇讲过，一次提交除了项目快照，还包含作者、时间和说明。Git 不会根据你当前登录的网页账号自动猜测作者身份，需要先配置姓名和邮箱。

设置全局姓名：

```bash
git config --global user.name "你的名字"
```

设置全局邮箱：

```bash
git config --global user.email "you@example.com"
```

请把示例值替换成你希望写入提交记录的身份。引号把包含空格的名字作为一个整体传给 Git。

`git config` 用于读取和修改 Git 配置。`--global` 表示这项配置属于当前系统用户，通常会成为你新建仓库的默认值。它不是“上传到全球”的意思，也不会自动修改已经存在的提交。

## 查看刚才的配置

读取单个值：

```bash
git config --global user.name
git config --global user.email
```

查看全局配置及其来源文件：

```bash
git config --global --list --show-origin
```

输出会包含来源路径、配置名和值。公开截图或求助时先检查其中是否有代理地址、凭据辅助配置或其他不希望公开的信息。

## 配置有不同作用范围

Git 常见配置范围从大到小是：

1. 系统配置：影响一台电脑上的所有用户；
2. 全局配置：影响当前系统用户；
3. 仓库配置：只影响某个仓库。

更具体的配置会覆盖更宽泛的配置。仓库配置需要先有仓库，下一章创建后再演示。

例如，个人项目使用私人邮箱，公司项目使用工作邮箱，可以进入公司项目目录后设置：

```bash
git config user.email "work@example.com"
```

没有 `--global` 时，Git 默认修改当前仓库的配置。如果当前目录不在仓库中，这条命令会失败。现在不要执行，等创建练习仓库后再尝试。

## 作者与提交者

Git 提交内部可以同时记录作者和提交者。大多数直接创建的提交中，两者相同；代为应用补丁或重写历史时可能不同。本篇只需要记住作者身份，后面分析历史改写时再解释两者差异。

## 常见错误与修正

### 拼错了姓名或邮箱

在还没有创建提交时，重新执行正确的配置命令即可。已经创建提交后，改配置不会追溯修改旧历史。第五篇会区分“修改本地提交”和“修改已推送提交”的不同风险。

### 把令牌或密码写进邮箱配置

`user.email` 只应是提交中展示的邮箱，不是登录凭据。GitHub 等平台可提供隐私邮箱；是否使用取决于你的公开身份策略。

## 动手试试

设置姓名和邮箱，然后分别读取它们。不要把个人隐私值复制到公开问题中；只需要确认终端返回的是预期内容。
