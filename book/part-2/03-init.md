# 创建第一个仓库：git init

## 创建独立练习目录

本篇的所有操作都应在练习目录中完成。下面两条是终端的目录操作，不是 Git 命令：

```bash
mkdir git-first-lab
cd git-first-lab
```

`mkdir` 创建目录，`cd` 进入目录。如果目录已经存在，不要覆盖里面的内容；换一个新名字重新创建。

## 初始化仓库

在空的练习目录中执行：

```bash
git init --initial-branch=main
```

`git init` 把当前目录初始化为 Git 仓库。`--initial-branch=main` 指定第一条分支以后使用 `main` 这个名字。分支的准确模型会在第三篇解释；现在只把它看作主工作线的名称。

输出类似：

```text
Initialized empty Git repository in .../git-first-lab/.git/
```

第一篇说过，一个项目包含可编辑文件和 Git 管理的数据。初始化创建的 `.git` 目录就是当前仓库的数据区域。它在许多系统中默认隐藏。

## 初始化没有做什么

`git init`：

- 没有创建提交；
- 没有把目录中的文件自动加入历史；
- 没有连接 GitHub 或其他服务器；
- 没有上传任何内容。

它只是准备好一个可以记录历史的本地仓库。分布式模型从这里就能看出来：创建本地仓库不需要远程账号。

## 仓库级配置

现在可以演示上一章暂缓的仓库配置。读取全局邮箱：

```bash
git config --global user.email
```

如果这个练习仓库需要使用另一个邮箱，可以设置：

```bash
git config user.email "lab@example.com"
```

再读取当前生效值：

```bash
git config user.email
```

为了让后续实验提交使用你真正配置的全局身份，如果刚才设置了实验邮箱，请删除这项仓库覆盖：

```bash
git config --unset user.email
```

`--unset` 删除指定配置项。它不会删除仓库或提交。

## 错误示范：删除 `.git`

不要通过删除 `.git` 来“清理看不懂的文件”。当前项目的提交、分支和仓库配置都保存在这里。练习仓库还没有历史，删掉影响不大；真实项目中这可能让本地历史和未分享提交消失。

如果在错误目录执行了 `git init`，先停止继续操作。确认那个目录中没有需要保留的 Git 历史后，再决定是否移除误建的 `.git`。不要在路径不明确时执行递归删除命令。

## 结果检查

下一章会正式学习状态命令。现在只要确认初始化输出包含 `.git` 路径，并保持终端仍位于 `git-first-lab` 目录。
