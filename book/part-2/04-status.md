# 先观察再操作：git status

## Git 当前知道什么

初始化之后，先不要急着提交。执行：

```bash
git status
```

`git status` 读取仓库状态，不修改文件或历史。空仓库的输出会说明当前位于 `main`，还没有提交，并且没有可提交内容。

状态命令是本书最重要的安全习惯：在执行会改变状态的操作之前和之后都运行一次，用实际输出代替猜测。

## 创建第一个文件

用编辑器在 `git-first-lab` 中创建 `README.md`，内容如下：

```markdown
# Git First Lab

这是我的第一个 Git 练习仓库。
```

保存后再次执行：

```bash
git status
```

输出会出现 `Untracked files`，并列出 `README.md`。

本书把**未跟踪文件**定义为：当前工作目录中存在，但还没有进入 Git 已记录文件集合的文件。Git 看见了它，却不知道你希望把它纳入版本控制，还是希望忽略它。

## 状态输出的三层信息

完整状态通常按以下顺序组织信息：

1. 当前工作位置；
2. 已经为下次提交准备的变化；
3. 尚未为下次提交准备的变化和未跟踪文件。

现在只出现未跟踪文件。下一章解释“为下次提交准备”所指的中间区域。

## 简短状态

当你熟悉完整输出后，可以使用：

```bash
git status --short
```

也可以写成短选项：

```bash
git status -s
```

对于当前文件，会看到类似：

```text
?? README.md
```

`??` 表示未跟踪。简短状态适合快速扫描，完整状态更适合初学和事故现场，因为它会给出下一步提示。

## 常见错误

### 把状态输出当作错误

未跟踪、已修改或存在冲突都是状态，不等于 Git 程序运行失败。先读清每一组文件处于什么区域，再决定是否操作。

### 只看终端提示符上的分支名

终端主题可能缓存或简化信息。需要判断真实状态时，以 `git status` 和后续学习的历史命令为准。

## 动手试试

分别运行完整和简短状态。确认 `README.md` 仍然只是普通文件，内容没有被命令改变。下一章会解释怎样把它准备为第一次提交。
