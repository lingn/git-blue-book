# 阅读历史：git log 与 git show

仓库现在至少有两条提交。我们开始从历史一侧观察，而不是只查看尚未提交的变化。

## 查看提交列表

```bash
git log
```

`git log` 按从新到旧的顺序显示当前历史。每条记录通常包含：

- 完整提交 ID；
- 作者；
- 创建时间；
- 提交说明。

输出进入分页器时按 `q` 返回终端。

紧凑查看：

```bash
git log --oneline
```

输出类似：

```text
7d8e9f0 docs: explain repository purpose
1a2b3c4 docs: add project introduction
```

前面的短字符串是提交 ID 的缩写。你的值一定不同，因为提交内容、身份、时间和父提交都会参与标识计算。

## 查看一条提交的完整变化

复制你第一条提交的短 ID，执行：

```bash
git show 1a2b3c4
```

把示例 ID 替换成你的真实值。`git show` 展示指定对象；当参数是提交 ID 时，会显示提交信息和它引入的差异。

如果只想看文件统计：

```bash
git show --stat 1a2b3c4
```

如果不提供 ID：

```bash
git show
```

Git 默认展示当前历史最新提交。第三篇会给“当前历史位置”一个准确名称。

## 提交 ID 为什么可以缩写

完整 ID 很长。Git 允许使用足以在当前仓库中唯一识别对象的前缀。仓库增长后，过短前缀可能不再唯一；工具显示的默认长度会相应处理。

不要在文档、自动化或跨仓库沟通中随意截成固定四位。需要精确指向时，使用 `git log --oneline` 当前显示的值，或者复制完整 ID。

## 查看历史不是查看远程平台

`git log` 读取本地仓库。网页上的提交列表与本地不同，通常意味着两边尚未交换最新历史，或者你查看的不是同一条工作线。它不意味着 Git 随机丢失提交。

## 只读命令是排障起点

到这里学过的主要只读命令包括：

```bash
git status
git diff
git diff --staged
git log
git show
```

遇到异常时，优先用它们收集证据。不要因为历史“看起来不对”就立即执行重置、强制推送或删除操作。

## 动手试试

用 `git log --oneline` 找到两条提交，再分别用 `git show --stat <提交ID>` 检查。尝试解释每条提交完成了什么，而不是只复述修改了哪个文件。
