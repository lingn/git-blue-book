# 分支不是文件夹

## 直接记提交 ID 不现实

每创建一次提交，最新节点都会得到新的 ID。如果每天都要手工记住“功能开发现在到了哪个提交”，既低效又容易出错。Git 使用一个可以移动的名字指向提交。

本书把**引用**定义为：指向某个 Git 对象的名字。分支是最常用的一类引用，它指向一条工作线当前最新的提交。

```text
A <- B <- C
          ^
          main
```

这里 `main` 指向 C。创建新提交 D 后，当前分支会自动向前移动：

```text
A <- B <- C <- D
               ^
               main
```

旧提交仍然存在，移动的是名字。

## 查看现有分支

```bash
git branch
```

不带参数的 `git branch` 列出本地分支。当前练习仓库只有：

```text
* main
```

星号表示你当前位于这个分支。`git branch` 在这里是只读操作，没有创建或切换任何东西。

同时查看分支和它指向的提交：

```bash
git branch --verbose
```

也可以写成 `git branch -v`。输出会包含短提交 ID 和最新提交说明。

## 创建分支为什么便宜

如果分支是项目目录的完整副本，创建分支就需要复制所有文件。Git 分支主要只是一个引用，创建时只需要让新名字指向已有提交。

```text
              main
                v
A <- B <- C
          ^
       feature
```

此时 `main` 和 `feature` 可以指向同一个 C。项目内容没有复制两份，历史也没有分裂；只有当其中一条工作线创建新提交，两个名字才会指向不同节点。

## 分支名不是目录路径

团队常使用 `feature/login`、`fix/rounding` 这样的名字表达类别。斜杠只是名字结构的一部分，不会在项目中创建 `feature` 目录，也不会决定代码文件放在哪里。

分支也不是一组提交的容器。更准确地说，分支指向一个提交；从该提交沿父关系可以到达的节点构成它当前可见的历史。

## 删除分支意味着什么

删除分支主要是删除这个名字，不会逐个删除它经过的提交。只要其他分支或标签仍能到达那些提交，历史仍然正常可见。即使名字误删，Git 通常也有恢复线索，第五篇会用引用日志找回。

现在不要尝试删除。先学会安全创建和切换。

## 小结

分支是指向提交、并会在当前工作线上创建新提交时向前移动的引用。下一章要回答：多个分支同时存在时，Git 如何知道你当前在哪一个？
