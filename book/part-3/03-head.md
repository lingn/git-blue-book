# 当前所在位置：理解 HEAD

仓库可以有多个分支，但一次只能有一个当前工作位置。Git 使用一个名为 `HEAD` 的特殊引用记录它。

## 正常状态下，HEAD 指向当前分支

```text
HEAD
  |
  v
main -> C
```

通常不要把 `HEAD` 简单说成“最新提交”。更准确的工作模型是：`HEAD` 指向当前分支，而当前分支再指向提交。

创建新提交时发生两件事：

1. 新提交把当前提交记录为父提交；
2. 当前分支移动到新提交，`HEAD` 仍指向这个分支。

## 查看 HEAD 指向的分支

```bash
git branch --show-current
```

在练习仓库中应输出：

```text
main
```

还可以读取 `HEAD` 所代表的提交：

```bash
git show --no-patch --oneline HEAD
```

这里第一次把 `HEAD` 当作命令参数。Git 在需要提交的位置接受名字或 ID；`HEAD` 会解析为当前提交。

因此上一篇的：

```bash
git show
```

在没有指定对象时，通常就是展示 `HEAD` 当前代表的提交。

## 相对写法：HEAD 的父提交

`HEAD~1` 表示沿第一个父关系向过去走一步：

```bash
git show --no-patch --oneline HEAD~1
```

`HEAD~2` 表示连续走两步。这些写法以后会用于比较和恢复，但不要在历史长度不足时照抄；第一条提交没有父提交。

## 分离状态是什么

Git 也允许 `HEAD` 直接指向某个提交，而不通过本地分支：

```text
HEAD -> B
main -> C
```

这叫 `HEAD` 分离状态，常用于临时查看旧版本。此时仍可创建提交，但没有普通分支名替你保留工作位置，离开前需要额外处理。

本章只建立概念，不主动进入分离状态。后面讲标签、变基和恢复时会再次遇到，并给出安全离开方法。

## 常见误解

### “HEAD 永远是 main”

切换到其他分支后，`HEAD` 会跟随新分支。仓库的默认分支叫 `main`、`master` 或其他名字，都不影响这个机制。

### “HEAD 是整个仓库最新提交”

不同分支可以有各自最新提交，Git 没有一个脱离工作线的全局“最新”。`HEAD` 表示当前上下文。

## 小结

分支给提交位置命名，`HEAD` 记录当前分支。理解这两层引用后，创建和切换分支就不再是神秘的目录替换。
