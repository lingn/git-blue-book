# 给重要提交命名：git tag

分支会随新提交移动，但发布版本需要一个稳定名字长期指向同一提交。Git 使用标签完成这件事。

## 标签的工作模型

**标签**是给特定 Git 对象的稳定名字，日常几乎总是标记提交。与分支不同，创建标签后继续提交，标签不会自动向前移动。

```text
v0.1.0
   |
   v
A <- B <- C  main
```

## 查看已有标签

```bash
git tag
```

新仓库没有标签时不会输出内容。

## 创建带说明的标签

先确认当前提交确实是要标记的版本：

```bash
git status
git show --no-patch --oneline HEAD
```

创建附注标签：

```bash
git tag -a v0.1.0 -m "First Git workflow lab release"
```

`-a` 创建附注标签；`-m` 提供标签说明。附注标签自身保存创建者、时间和说明，适合发布节点。

查看：

```bash
git show v0.1.0
```

输出先显示标签信息，再显示被标记提交。

## 轻量标签

```bash
git tag experiment-1 HEAD~1
```

不带 `-a` 时创建轻量标签，它更像一个直接指向提交的名字。参数 `HEAD~1` 指当前提交的第一父提交。这个实验标签不是正式发布。

删除它：

```bash
git tag -d experiment-1
```

`-d` 只删除标签引用，不删除提交。

## 标签默认也只在本地

创建标签不会自动上传。第四篇学习远程仓库后，会使用：

```text
git push origin v0.1.0
```

现在不要执行；练习仓库还没有名为 `origin` 的远程地址。这里展示只是说明标签与分支一样需要显式分享。

## 错误标签怎样处理

如果尚未分享，可以删除后在正确提交上重建。标签已经用于发布后，移动同名标签会让不同人看到不同版本，风险很高。更稳妥的做法通常是创建新的修订版本标签，并记录旧版本问题。

## 小结

分支是会随工作移动的引用，标签是稳定标记。两者都给提交位置命名，但生命周期和团队语义不同。
