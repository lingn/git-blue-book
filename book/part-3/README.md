# 第三篇：用分支组织并行工作

这一篇先解释提交之间如何连接，再引入分支与 `HEAD`。读者不会在理解这些名字之前被要求执行合并或变基。

计划章节：

1. 提交如何组成历史：父提交与提交图
2. 分支不是文件夹：可移动名字的工作模型
3. 当前所在位置：理解 `HEAD`
4. 创建和切换分支：`git branch` 与 `git switch`
5. 把两条历史合到一起：`git merge`
6. 快进合并与合并提交分别发生了什么
7. 冲突不是报错：三方合并在等你决定什么
8. 完整处理一次冲突，并验证最终结果
9. 给重要提交命名：`git tag`

篇末综合场景：在功能开发期间插入一个紧急修复，再把两条工作线安全合并。
