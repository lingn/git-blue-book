# 复制完整仓库：git clone

## 克隆一个公开仓库

选择一个不包含现有项目的新目录，执行：

```bash
git clone https://github.com/lingn/git-blue-book.git
```

`git clone` 从给定地址复制仓库，并创建工作目录。命令最后一段是仓库 URL；这里使用本书公开仓库作为只读练习。

默认会创建名为 `git-blue-book` 的目录。也可以指定本地目录名：

```bash
git clone https://github.com/lingn/git-blue-book.git git-book-reading
```

如果目标目录已存在且非空，Git 会拒绝，避免与现有文件混在一起。

## clone 完成了哪些事

一次普通克隆通常会：

1. 创建新的本地仓库；
2. 下载远程可达的提交和其他对象；
3. 把来源地址记录为一个远程仓库；
4. 建立本地远程跟踪引用；
5. 创建并切换到默认本地分支；
6. 把该提交的快照写入工作区。

所以克隆得到的不只是最新文件，也包含可供本地查看的历史。

进入目录后验证：

```bash
cd git-book-reading
git status
git log --oneline -5
```

`-5` 要求最多显示五条历史。即使断开网络，这些已经下载的提交仍能查看。

## 克隆不会授予写权限

公开仓库通常允许任何人读取，但推送仍需要仓库写权限和有效凭据。能够 `clone` 不代表能够 `push`。

## 克隆与下载 ZIP 的区别

ZIP 通常只包含某个版本的文件，没有 `.git` 历史和远程关系。它适合取得一份静态源码，不适合继续完整 Git 协作。克隆则得到可提交、分支和获取更新的本地仓库。

## 不要复制来源仓库的 `.git` 目录

克隆会创建属于新本地仓库的配置和引用。手工复制其他项目的 `.git` 目录可能带入错误远程地址、钩子或本地配置，不是创建正常工作副本的方法。

## 小结

`clone` 是“创建本地仓库 + 获取历史 + 建立远程关系 + 检出默认分支”的组合动作。下一章查看它记录的远程名称和地址。
