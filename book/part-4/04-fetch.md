# 只获取、不整合：git fetch

## 安全查看远程有没有新历史

```bash
git fetch origin
```

`git fetch` 与指定远程通信，下载本地缺少的对象，并更新本地对应的远程跟踪引用。它不会把远程文件直接覆盖到当前工作区，也不会自动移动当前本地分支。

这使 `fetch` 成为协作排查中的低风险第一步：先更新“我所知道的远程状态”，再决定怎样处理。

## 输出怎样读

远程没有变化时可能几乎没有输出。有新分支或提交时，会看到类似：

```text
abc1234..def5678  main       -> origin/main
 * [new branch]   feature/x  -> origin/feature/x
```

右侧 `origin/main` 和 `origin/feature/x` 都是本地远程跟踪引用。输出表示本地记录已更新，不表示本地 `main` 已经合并这些提交。

## 获取所有已配置远程

```bash
git fetch --all
```

`--all` 依次获取所有远程。只有一个 `origin` 时没有必要为了形式使用它。获取多个远程也不会把它们相互合并。

## 清理远程已删除的分支记录

服务器删除分支后，本地旧的远程跟踪引用可能继续存在。获取时清理：

```bash
git fetch --prune origin
```

`--prune` 删除本地已确认在该远程不存在的远程跟踪引用。它不会删除同名本地分支。

## 获取失败时不会怎样

认证失败、网络中断或地址错误时，Git 不会把半下载内容当作新的完整远程状态，也不会修改工作区。先读错误中的目标主机和权限信息，不要用重置或删除仓库解决连接问题。

## 获取标签

与所获取分支历史相关的标签通常会一并取得。如果需要显式获取所有远程标签，可以使用：

```bash
git fetch --tags origin
```

标签与分支的发布细节会在推送章节说明。

## 小结

`fetch` 更新本地对远程的认知，不替你决定是否以及怎样整合。下一章学习读懂 `origin/main` 与 `main` 的距离。
