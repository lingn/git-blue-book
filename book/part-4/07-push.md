# 发布本地提交：git push 与上游分支

## push 请求远程移动引用

本地创建的提交不会自动出现在远程。发布当前 `main`：

```bash
git push origin main
```

参数顺序是远程名称、要发布的本地分支。Git 会发送远程缺少的对象，并请求远程把对应分支更新到新提交。

如果你对目标仓库没有写权限，命令会在认证或授权阶段失败。本地提交仍保留，不需要重新创建。

## 第一次推送新分支

创建并提交功能分支后：

```bash
git push --set-upstream origin feature/search
```

常用短写：

```bash
git push -u origin feature/search
```

`-u` 在成功推送时为当前本地分支记录上游关系。以后位于该分支时，通常可直接使用：

```bash
git push
git pull --ff-only
```

上游关系回答“当前本地分支默认与哪个远程跟踪分支比较和交换”，不表示两边会自动同步。

## 查看跟踪关系

```bash
git branch -vv
```

第二个 `v` 会显示上游名称和领先、落后信息。先 `fetch` 后再把这些状态当作当前证据。

## 推送标签

分支推送不会默认发送所有本地标签。发布一个明确标签：

```bash
git push origin v0.1.0
```

也存在一次推送多个标签的选项，但发布流程更适合明确选择已验证版本，避免把实验标签一起公开。

## 删除远程分支

功能合并且团队确认无需保留时：

```bash
git push origin --delete feature/search
```

这会请求删除远程分支引用，不删除已经被其他分支包含的提交。它是共享状态变更，执行前应确认评审、部署或同事工作不再依赖该分支。

## 推送成功后仍要确认平台结果

终端成功表示远程接受了引用更新，不代表持续集成、评审或部署成功。检查平台上的目标分支、提交 ID 和后续检查状态。

## 不要默认强制推送

普通推送被拒绝通常是在保护远程新增历史。不要立即加 `--force`。下一章会制造两位开发者同时推送的场景，解释拒绝为什么发生以及安全处理顺序。
