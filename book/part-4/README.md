# 第四篇：与远程仓库和团队协作

这一篇会始终区分“远程服务器上的状态”“本地保存的远程快照”和“当前本地分支”，避免把 `pull` 当作不可解释的魔法命令。

计划章节：

1. 远程仓库到底远在哪里
2. 复制完整仓库：`git clone`
3. 查看和管理远程地址：`git remote`
4. 只获取、不合并：`git fetch`
5. 远程跟踪分支记录了什么
6. `git pull` 实际组合了哪两步
7. 发布本地提交：`git push` 与上游分支
8. 多人同时推送时，为什么会被拒绝
9. 代码评审前整理本地历史
10. 变基的本质：重新生成一段提交
11. 安全使用 `git rebase`，以及何时不该使用
12. 只迁移需要的提交：`git cherry-pick`

篇末综合场景：同步主分支、整理功能分支并提交代码评审，全程不覆盖同事的历史。
