# 补充最近一次本地提交

## 场景：刚提交就发现漏了文件

最近一次提交完成同一个任务，但漏掉一项小修改。该提交尚未推送，也没有同事基于它工作。

先查看最近提交和当前变化：

```bash
git show --stat --oneline HEAD
git status
git diff
```

完成遗漏内容，加入暂存区并检查：

```bash
git add <遗漏文件>
git diff --staged
```

用暂存内容替换最近一次提交，同时保留原说明：

```bash
git commit --amend --no-edit
```

`--amend` 创建一条新提交，父提交与原提交相同，快照采用当前暂存区；`--no-edit` 保留原提交说明，不打开编辑器。

## amend 不是给旧提交追加附件

原提交不会原地变化。新提交的内容或提交者时间不同，因此 ID 改变：

```text
修改前：A <- B
修改后：A <- B'
```

当前分支从 B 改为指向 B'。B 暂时可能通过引用日志找回，但已不属于当前分支历史。

## 验证替换结果

```bash
git status
git show --stat --oneline HEAD
```

确认遗漏内容进入提交、工作区没有意外变化，并运行测试。

## 什么时候不应直接 amend

- 最近提交已经推送并被别人获取；
- 遗漏内容其实属于另一个意图；
- 需要修改的不是最近一条提交；
- 不清楚当前暂存区还有什么。

第一种情况会改写公开历史；第二种应创建独立提交；第三种需要交互式变基；第四种先清理暂存区。

## amend 只使用暂存区

工作区中尚未暂存的其他修改不会自动进入新提交。这既是保护，也是常见困惑。提交前始终检查 `git diff --staged`。
