# 只修改最近一次提交说明

## 场景：内容正确，说明写错

最近一次本地提交的文件内容正确，但说明含有错别字、错误任务号或无法表达意图。它尚未分享。

先确认修改对象：

```bash
git status
git show --no-patch --format=fuller HEAD
```

工作区最好保持干净。直接提供新说明：

```bash
git commit --amend -m "docs: clarify recovery workflow"
```

这会用相同快照和父提交创建新提交，但提交说明与提交者信息变化，因此 ID 仍会改变。

## 使用编辑器修改长说明

```bash
git commit --amend
```

Git 打开配置的编辑器，显示原说明。修改、保存并退出后创建替代提交。若不熟悉编辑器，先学习其保存和退出方式，或者使用明确的 `-m` 参数。

## 作者与提交者的区别

普通 amend 通常保留原作者信息，但更新提交者和提交者时间。历史页面可能同时显示 author 与 committer。不要用 amend 假装他人创作，也不要随意修改审计身份。

## 已推送后的影响

即使只改一个字，提交 ID 也改变。远程仍指向旧提交，普通推送会被拒绝。如果这段历史已经公开，先判断：

- 是否真的值得为说明改写共享历史；
- 平台是否允许直接编辑展示信息而不改提交；
- 团队是否明确允许个人评审分支重写；
- 是否需要通知已开始评审的人。

主分支和发布分支通常不应为了美化说明而重写。

## 验证

```bash
git log -1 --format=fuller
git show --stat --oneline HEAD
```

确认说明正确且文件统计未出现意外变化。
