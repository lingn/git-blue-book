# 只修改最近一次提交说明

## 场景：内容正确，说明写错

最近一次本地提交的文件内容正确，但说明含有错别字、错误任务号或无法表达意图。它尚未分享。

先确认修改对象：

```bash
git status
git show --no-patch --format=fuller HEAD
```

工作区最好保持干净。直接提供新说明：

```bash
git commit --amend -m "docs: clarify recovery workflow"
```

这会用相同快照和父提交创建新提交，但提交说明与提交者信息变化，因此 ID 仍会改变。

## 使用编辑器修改长说明

```bash
git commit --amend
```

Git 打开配置的编辑器，显示原说明。修改、保存并退出后创建替代提交。若不熟悉编辑器，先学习其保存和退出方式，或者使用明确的 `-m` 参数。

## 作者与提交者的区别

普通 amend 通常保留原作者信息，但更新提交者和提交者时间。历史页面可能同时显示 author 与 committer。不要用 amend 假装他人创作，也不要随意修改审计身份。

## 把作者也重置为当前身份：--reset-author

普通 amend 帮不了另一种常见事故：身份本身配错了。比如在新机器上忘记配置身份，或把个人邮箱提交进了公司仓库，最近一条提交的 author 不是你想要的身份。先按第二篇身份配置一章修正 `user.name` 和 `user.email`，再让最近一次提交按当前配置重新署名：

```bash
git commit --amend --no-edit --reset-author
```

`--no-edit` 保留原说明；`--reset-author` 把 author 和作者时间重置为当前配置的身份与当前时间，committer 照常更新。

```bash
git log -1 --format=fuller
```

输出的 author 与 committer 两行应一致地显示修正后的身份。

文件内容不变，但署名是提交内容的一部分，提交 ID 仍会改变。如果这条提交已经推送，先按下一节的标准判断值不值得改写。`--reset-author` 的正当用途是修正自己的署名错误，不是把他人的提交改挂到自己名下。需要修正的提交不止一条时，单条 amend 不够，下一章会用变基配合 `--exec` 逐条处理。

## 已推送后的影响

即使只改一个字，提交 ID 也改变。远程仍指向旧提交，普通推送会被拒绝。如果这段历史已经公开，先判断：

- 是否真的值得为说明改写共享历史；
- 平台是否允许直接编辑展示信息而不改提交；
- 团队是否明确允许个人评审分支重写；
- 是否需要通知已开始评审的人。

主分支和发布分支通常不应为了美化说明而重写。

## 验证

```bash
git log -1 --format=fuller
git show --stat --oneline HEAD
```

确认说明正确且文件统计未出现意外变化。
