# 第五篇：撤销、回滚与找回

这一篇不从命令分类出发，而是先判断两个边界：改动有没有成为提交，相关历史有没有推送给别人。相同目标在不同边界下会使用不同策略。

计划章节：

1. 先别急着撤销：用状态矩阵判断当前位置
2. 丢弃工作区修改：`git restore`
3. 取消暂存，但保留文件修改
4. 修改最近一次本地提交：`git commit --amend`
5. 只修改最近一次提交说明
6. 修改多个本地提交：交互式变基
7. 已推送提交如何回滚：`git revert`
8. 为什么已公开历史不应随意改写
9. 必须更新远程历史时：`--force-with-lease`
10. 理解 `git reset` 的三种模式
11. 用引用日志找回“消失”的提交：`git reflog`
12. 找回误删分支、错误重置和失败变基前的状态

篇末综合场景：分别处理未提交误改、错误提交、错误推送和误删分支，并解释每种恢复方式为什么安全。
