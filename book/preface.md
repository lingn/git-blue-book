# 前言：这不是一本命令字典

Git 难学，通常不是因为命令太多，而是同一句“撤销修改”可能指向完全不同的事情：

- 丢弃一个还没保存进历史的工作区改动；
- 把错误暂存退回工作区；
- 修改刚刚创建的本地提交；
- 撤销已经推送给团队的共享提交；
- 找回被错误移动或删除的分支；
- 把一个候选提交与制品和运行实例重新对上。

这些动作表面相似，安全做法却不同。命令名称只能告诉你“要做什么类型的动作”，不能告诉你当前文件、index、对象、引用和远端处于什么状态。

## 本书先回答三个问题

本书不会从一张巨大的命令速查表开始，而是沿着三个问题推进：

1. Git 在保存什么？
2. 当前变化位于哪里？
3. 这段历史是否已经被别人看到？

第一个问题引出快照、对象、提交和引用。第二个问题引出工作区、index、HEAD 和进行中操作。第三个问题引出远程跟踪、评审、保护规则、制品、部署和恢复责任。

当这三个问题有了答案，命令就变成对状态的明确操作，而不是需要碰运气的口诀。

## 你会得到什么

读完基础部分，你应该能：

- 画出一个提交的父关系和快照入口；
- 解释工作区、index 和 HEAD 的差异；
- 判断分支是否包含某个提交；
- 选择 merge、rebase、cherry-pick、revert 或 reset；
- 从远程跟踪引用中区分“我上次知道什么”和“服务器现在是什么”；
- 在提交、推送、冲突和恢复前后核对 OID 和状态。

读完工程部分，你还应该能：

- 为 stash、worktree 和 bisect 选择合适的工作方式；
- 为评审候选、CI、制品和部署建立证据链；
- 处理大仓库、LFS、子模块、subtree 和 monorepo 的边界；
- 识别凭据、签名、hooks、filters 和第三方依赖的供应链风险；
- 保护事故现场，恢复对象和引用，执行迁移或故障切换；
- 把具体症状分流到可执行的排障和组织治理流程。

本书的标准不是“记住多少命令”，而是发生异常时能否说明作用对象、风险边界、恢复来源和验证证据。

## 章节怎样组织

基础读者可以按第一篇到第六篇顺序阅读：

1. 第一篇解释版本控制、分布式仓库和快照；
2. 第二篇完成一次可靠的本地提交；
3. 第三篇建立提交图、分支和合并模型；
4. 第四篇进入远程仓库、同步、评审、rebase 和 cherry-pick；
5. 第五篇处理撤销、回滚、改写和恢复；
6. 第六篇把这些能力放进真实工程工作流。

第七篇是 v2 的改写、撤销与恢复目标篇，迁移完成前仍通过第五篇兼容入口阅读。第八至十三篇分别进入发布与 CI/CD、规模与仓库组合、安全与供应链、取证与恢复、组织治理和症状排障。

如果你是 Tech Lead、DevOps/SRE 或研发效能负责人，可以直接从第三篇的对象与提交图开始，再读第六、八、十、十二、十三篇。事故现场优先查看场景索引和第十三篇，不需要从头通读。

## 每个命令都要有操作契约

本书中的命令和实验尽量说明：

- 前置条件：Git 版本、操作系统、权限、网络和仓库形态；
- 执行位置：普通工作区、linked worktree、裸仓库、客户端或接收端；
- 状态变化：工作区、index、对象、refs、远程缓存或平台状态；
- 预期输出：哪些值是变量，哪些关系必须成立；
- 失败方式：错误发生在哪一层，如何取得判别证据；
- 恢复办法：从哪个 OID、tree、stash、reflog、bundle 或备份恢复；
- 安全边界：哪些操作会覆盖文件、改写共享历史、泄漏凭据或触发清理；
- 验收方法：动作完成后检查哪个不变量、测试或外部记录。

代码块里的命令可以直接复制到专用练习环境，不能不加判断地用于真实项目。占位符、路径、提交 ID、远程 URL 和平台名称必须替换为已经核对的值。

## 实验和真实系统的边界

仓库提供的实验使用临时目录、合成身份和本地 Git 行为。它们适合验证：

- 对象、提交、引用和 index 的关系；
- 分支、合并、rebase、revert、reset 和 reflog；
- 本地 bare 仓库的传输和引用更新；
- 受限克隆、LFS pointer、子模块 gitlink 和构建摘要的模型；
- 证据清单、状态门禁和恢复动作的逻辑。

它们不能冒充：

- GitHub、GitLab 或其他平台的权限、评审、规则和审计；
- SSH 主机密钥、HTTPS TLS、SSO、令牌和真实凭据助手；
- CI runner、制品仓库、数据库、消息系统和部署实例；
- 文件系统取证、区域故障、真实 RPO/RTO 和组织值班响应。

平台、计费、权限、界面和默认策略会变化。正文优先使用厂商无关抽象，必要的实例必须标明版本、核对日期和来源。自动实验通过只是本地证据通过，不是出版标准或生产安全证明。

## 先保护，再操作

遇到看不懂的状态时，先停止连续试命令。保存：

~~~bash
git status --short --branch --untracked-files=all
git diff --no-ext-diff --no-textconv
git diff --no-ext-diff --no-textconv --staged
git log --graph --decorate --oneline --all
git for-each-ref --format='%(refname) %(objectname) %(objecttype)'
~~~

如果可能涉及安全事件、对象损坏、历史取证或组织级故障，先进入相应的冻结和证据流程。不要让一次“修复尝试”替原始现场决定什么已经丢失。

## 关于文字和版本

本书使用中文解释 Git 的通用概念，命令、配置键、路径、对象类型和平台术语保留其实际写法。示例中的姓名、邮箱、URL、工单号和数据都是合成值。技术事实以 Git 官方文档、源代码说明、当前版本记录和可重复实验为依据，易变的平台事实不会写成永久默认值。

本书仍在 v2 重构中。章节、目录、实验和进度会逐步迁移，出版候选要等跨章去重、平台复核、独立技术审读和目标读者试读全部完成。
