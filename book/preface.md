# 前言：这不是一本命令字典

Git 难学，通常不是因为命令太多，而是同一句“撤销修改”可能指向完全不同的事情：丢弃一个还没保存进历史的文件改动、取消暂存、修改刚提交的内容、撤销已经推送给团队的提交，或者找回被错误移动的分支。它们表面相似，安全做法却不同。

因此，本书不会先给出一张巨大的命令速查表。我们会先回答三个问题：

1. Git 在保存什么？
2. 当前变化位于哪里？
3. 这段历史是否已经被别人看到？

当这三个问题有了答案，许多命令就不再需要死记。

## 关于章节结构

本书不会让每章机械重复相同的八个标题。概念章节、操作章节和事故恢复章节承担的任务不同，适合的节奏也不同。

大多数章节会从一个具体问题开始，用普通语言建立直觉，再给出准确的工作模型。需要操作时才引入新命令；适合验证的内容会提供可运行实验；存在数据风险时会单独给出错误示范和恢复方法。

章末的“动手试试”是可选内容，不是考试。每一篇结束后会设置一个综合场景，帮助读者确认自己能否把这一篇的知识连起来使用。
