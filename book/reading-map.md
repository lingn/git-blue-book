# 阅读路线

全书按知识依赖和工作角色组织。前一篇建立的模型，会成为后一篇处理复杂场景的工具。当前旧路径与 v2 专题并列保留，直到迁移门禁完成；导航标题以 `book/SUMMARY.md` 为准。

## 第一篇：Git 为什么会出现

从“文件名加 final 真的能管理版本吗”开始，理解集中式版本控制的局限、Git 的诞生背景，以及分布式版本控制真正改变了什么。这里不急着操作，先建立快照、历史和仓库的直觉。

## 第二篇：完成第一次可靠提交

配置环境，创建仓库，观察文件状态，逐步理解工作区、暂存区和提交。随后学习查看差异、阅读历史和忽略不应进入版本库的文件。

## 第二篇补充：连续工作状态与多个工作树

基础提交循环之外，补充阅读 stash 的临时对象模型和 linked worktree 的共享/隔离边界。需要长期协作、评审或发布时，转到第六篇和第八篇，不把临时状态当作共享历史。

## 第三篇（v2）：对象模型决定命令行为

深入对象的规范输入、SHA-1/SHA-256 格式、完整与缩写 OID、loose object、pack/index、delta 和对象生命周期，再进入逻辑引用、`HEAD`、reflog、提交图、可达性与 index 内部结构。最后用 porcelain/plumbing 边界解释高层工作流怎样组合底层原语，以及工具作者接管了哪些锁、恢复与策略责任。

## 第四篇（v2）：分支、合并与冲突

从本地分支、远程跟踪引用和 upstream 的区别开始，处理附着、分离、unborn `HEAD` 以及 linked worktree 的分支占用。合并与冲突章节覆盖 `ort`、复杂路径、abort/quit/continue、autostash 和 rerere；标签章再区分 ref、tag object、签名和发布证据。综合练习把主线热修复与功能整合串成一条可执行路径。

## 旧第三篇兼容入口

旧第三篇正文已经全部迁入 v2 第三、四篇，原 URL 继续保留为兼容入口。新读者不再从旧目录进入，外部链接仍可根据每页指引到唯一权威章节。

## 第五篇（v2）：远程仓库、协议与认证

先把服务器 refs、本次查询、本地 remote-tracking refs、本地分支、upstream、`FETCH_HEAD` 和平台控制面分开。Clone 与 fetch/pull 章节解释取得和整合，push 章节再按 source/destination、old/new OID、租约、atomic、push options 和服务端拒绝逐层验收。

## 第四篇：与远程仓库和团队协作

先区分本地仓库与远程仓库，再学习克隆、抓取、拉取和推送。之后进入远程跟踪分支和代码评审前的候选整理；rebase 与 cherry-pick 的旧入口保留在本篇，权威正文已经迁入第七篇。

## 第五篇（现行兼容入口）：撤销、回滚与找回

旧第五篇的正文已经迁入第七篇，本目录只保留外部链接兼容。新阅读不再从旧页面顺序进入。

## 第六篇（v2 权威稿）：共享历史的协作与评审

这一篇把功能头、目标基线、评审候选、审批、必需检查、合并队列和最终引用更新接成一条协作链。它比较 merge、squash 与 rebase merge 的对象后果，也把代码所有权、CI 报告者身份和紧急例外放进同一个可审计状态机。

## 旧第六篇兼容目录：把 Git 用进真实工程

旧目录继续保留 stash、worktree、bisect、热修复迁移、冲突报告、提交规范和排障的旧 URL。对应正文已经分别进入第二篇补充、第六篇、第八篇、第十一篇和第十三篇，旧页只承担兼容跳转。

## 第七篇（v2 权威稿）：改写、撤销与恢复

当修改已经进入工作区、index、本地提交或共享历史时，先用状态矩阵判断层级，再选择 restore、unstage、amend、rebase、cherry-pick、revert、reset 或 reflog。第七篇还覆盖显式租约、共享历史政策、远端改写事故和综合恢复，重点是共享边界、恢复引用，以及代码回退和数据回退为什么不能混为一谈。

## 第八篇：发布与 CI/CD 集成

如果你负责流水线、发布或部署，接着阅读第八篇。它把触发事件、实际 checkout、候选提交、制品摘要、数据库迁移、rollout 和事故到发布串成一条证据链。这里不把提交历史当作运行版本证明。

## 第九篇：大仓库、二进制与仓库组合

如果仓库很大，或项目包含二进制、LFS、子模块、subtree 和 monorepo，阅读第九篇。先测量对象、工作区和网络成本，再选择稀疏、部分克隆或拓扑拆分；每种选择都说明恢复和所有权代价。

## 第十篇：安全、签名与供应链

如果你负责凭据、CI 安全或来源证明，阅读第十篇。它区分传输认证、组织授权、对象签名、密钥状态、不受信任配置、秘密扫描和下游副本，避免用一个绿色标记代表整条信任链。

## 第十一篇：取证、迁移与灾难恢复

如果正在处理历史调查、仓库损坏、迁移或区域故障，先冻结现场，再从第十一篇开始。它给出对象、refs、bundle、mirror、平台数据和主备切换的分层恢复边界。

## 第十二篇：组织级运维与治理

如果你是 Tech Lead、DevOps/SRE 或研发效能负责人，阅读第十二篇。它覆盖仓库生命周期、权限回收、规则与例外、审计留存、容量预算和组织级恢复演练。

## 第十三篇：故障排查手册

如果你面对一个具体症状，不必从头阅读。根据“文件或提交不见”“push/认证失败”“仓库变慢”“LFS/子模块异常”“签名失败”“远程引用漂移”或“仓库损坏”进入第十三篇，并按证据优先顺序操作。
