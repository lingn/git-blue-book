# 首版完成标准

这份文件把用户目标、书籍规划和可验证证据对应起来。首版完成不表示以后不再修订，而是表示当前公开内容已经形成从零到真实工程场景的闭环。

## 需求与证据

| 要求 | 权威内容 | 完成证据 |
| --- | --- | --- |
| 从零开始，不默认版本控制知识 | 第一、二篇 | 从版本问题、仓库和对象模型开始，命令从版本检查逐步引入 |
| 解释 Git 由来和解决的问题 | 第一篇第 1-3 章 | 覆盖手工副本、集中式/分布式、2005 年 Linux 内核背景 |
| 解释底层原理 | 第一篇第 4-5 章、第三篇第 1-3 章 | 覆盖快照、blob/tree/commit/tag、内容寻址、提交图、引用与 HEAD |
| 聚焦常用命令而非命令全集 | 第二至第六篇、命令地图 | 命令按工作流引入，附录只索引正文已解释命令 |
| 能独立处理日常协作 | 第三、四篇 | 分支、合并、冲突、远程三层模型、推送拒绝、变基、挑选提交 |
| 修改最近提交内容与说明 | 第五篇第 4-5 章 | 区分 amend 内容、只改说明及提交 ID 变化 |
| 修改多个未分享提交 | 第五篇第 6 章 | 交互式变基动作、冲突、中止和共享边界 |
| 回滚已经推送的提交 | 第五篇第 7-9 章 | revert、公开历史边界、显式 force-with-lease 预期值 |
| 误操作后恢复 | 第五篇第 10-12 章 | reset 三区域、reflog、误删分支和失败变基恢复 |
| 真实特殊场景 | 第六篇 | stash、worktree、bisect、热修复、部署范围、优雅停机、发布复盘 |
| 公开阅读结构自然 | 前言、各篇 README、写作规范 | 按章节类型组织，普通章节不固定使用验收题，综合场景放在篇末 |
| 符合 GitBook 同步结构 | `.gitbook.yaml`、`book/SUMMARY.md` | `book/` 为根，79 个公开页面均被 SUMMARY 收录 |
| 示例可运行且高风险操作隔离 | `scripts/`、实验附录 | 8 套脚本只使用临时仓库和本地 bare 远程 |

## 自动检查

```bash
./scripts/verify-all.sh
```

总验证必须同时通过：

- 8 套 Git 行为实验；
- 所有 Shell 脚本语法检查；
- Markdown 本地链接检查；
- GitBook SUMMARY 页面覆盖检查；
- `git diff --check`。

## 人工检查

- 所有导航页面都有完整正文，不保留占位内容；
- 危险命令附近说明作用区域、共享边界和恢复路径；
- 未经授权不把真实公司、仓库、任务、提交或同事信息写进公开案例；
- Git 2.28+ 为命令基线，实验基线和官方来源已公开说明；
- 冲突、发布和回滚章节区分 Git 证据、业务验证与运行部署证据。
