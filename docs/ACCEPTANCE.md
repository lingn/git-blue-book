# v2 质量与出版验收标准

## 验收原则

自动检查用于发现回归，不能单独证明内容达到出版标准。章节只有在模型、事实、案例、实验、风险边界和文字质量都通过后才可标记完成。全书只有在跨章审校和目标读者试读完成后才可标记出版候选。

## 单章内容门槛

每章必须说明读者进入本章前需要知道什么，以及读完后能够判断或完成什么。概念要给出工作定义、适用边界和与相邻概念的区别；工程建议要说明约束条件、代价和反例；平台能力要先落到厂商无关抽象，再给带核对日期的实例。

命令和配置示例必须包含：

1. 前置条件，包括 Git 版本、操作系统或平台权限。
2. 执行位置，包括仓库、工作树、裸仓库、客户端或服务端。
3. 执行动作和参数含义。
4. 对工作区、index、对象、引用、远端或平台状态的变化。
5. 可观察的预期输出，并标出会变化的字段。
6. 常见失败方式和判别证据。
7. 恢复办法、验证动作和不可恢复边界。

高风险命令还要说明共享历史、并发协作者、凭据、数据丢失和 GC 窗口等安全边界。

## 实验门槛

- 实验默认在新建临时目录、本地容器或专用测试组织中运行，不让读者在真实项目试错。
- setup、act、assert、recover、cleanup 五个阶段可以分别执行和检查。
- 断言验证 Git 状态或平台状态，不只匹配一行演示输出。
- 输出中的提交 ID、时间、默认分支和本地路径标为变量，不伪造逐字一致性。
- 失败路径至少覆盖最常见的一种误用；恢复路径必须实际运行。
- 本地 bare 远程只能证明 Git 传输行为，不能冒充 GitHub、GitLab 或 CI 系统行为。
- 远端改写实验必须分别断言提交图左右计数、patch equivalence、远程跟踪 reflog、HEAD reflog 和恢复后的引用，不用提交说明相同代替对象与补丁证据。
- 依赖网络、套餐或管理员权限的实验要提供核对清单和证据记录，不伪造执行结果。

## 事实与来源门槛

- Git 核心行为优先使用 Git 官方文档、源码仓库文档和可重复实验交叉验证。
- 易变事实记录产品、版本、权限、计费影响、核对日期和来源链接。
- 性能结论说明硬件、操作系统、Git 版本、仓库规模、冷/热缓存和测量方法。
- 安全结论区分认证、授权、完整性、来源证明、机密性和审计。
- 单次事故和局部实验只能作为案例，不能直接写成通用规律。
- 引用内容可追溯，不复制来源不明的图表或大段文本。

## 结构与文字门槛

- 概念沿 `docs/MASTER-OUTLINE.md` 的依赖顺序引入，首次出现处承担权威解释。
- 同一清单或核心判断不在多个章节完整复述，后文使用链接并只写场景差异。
- 表格承担对照，正文补充原因、取舍和例外，不逐行复读。
- 基础读者、资深工程师、团队负责人和 SRE 都有连续阅读路径。
- 中文技术文字自然、准确，避免命令速查表式堆叠和空泛总结。
- 术语、分支名、示例角色、图例和风险标签全书一致。
- 公开内容通过隐私、匿名化、版权和敏感信息检查。

## 自动回归门禁

```bash
./scripts/verify-all.sh
```

总验证至少包括 Git 行为实验、Shell 语法、本地链接、GitBook 页面覆盖和 `git diff --check`。新增实验要进入总验证。中文新增或大改文档还要运行仓库采用的标点门禁。

## 出版候选门槛

- `docs/MASTER-OUTLINE.md` 中所有计划章节已落盘，没有用短篇占位。
- `docs/PROGRESS.md` 没有阻断性遗留项，所有完成状态能指向正文、实验或审校记录。
- 高风险章节经过独立技术审读，恢复命令在隔离环境复验。
- 至少由基础读者、资深工程师、Tech Lead 或 DevOps/SRE 三类读者完成路径试读并处理反馈。
- 平台事实完成发布前复核，过期信息已更新或标明日期。
- 全书完成跨章去重、术语索引、来源审查、图表审查和最终版式检查。
- 自动门禁全部通过，工作树中没有意外生成物或未解释的失败。

满足这些条件后，才能把状态从“重构中”改为“出版候选”。
