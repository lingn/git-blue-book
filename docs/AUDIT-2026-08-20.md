# 仓库内容审计，2026-08-20

## 审计范围与方法

本次审计覆盖仓库根文档、`book/` 下 79 个公开页面、`docs/` 的规划与验收文件，以及 8 组隔离实验。检查维度包括目录结构、知识依赖、内容重复、主题缺口、技术表述、案例完整度、实验可执行性、读者路径和出版成熟度。

基线执行 `./scripts/verify-all.sh` 已通过：脚本语法、8 组 Git 行为实验、本地链接、GitBook 导航覆盖和 `git diff --check` 均正常。这个结果只证明仓库当前可验证部分没有断裂，不代表内容已经达到出版标准。

## 现有资产

仓库已经形成六篇连续教程，正文约 5,000 行。第二至五篇的知识顺序较稳定：先讲工作区与暂存区，再讲提交图、引用、远程跟踪分支和共享历史，随后进入 rebase、cherry-pick、revert、reset 与 reflog。现有价值主要集中在以下几处：

- `book/part-1/05-first-model.md` 已建立 blob、tree、commit、tag 的基本对象模型，可作为底层篇的起点。
- 第三篇把分支、`HEAD`、三方合并和冲突按依赖顺序展开，结构合理。
- 第四篇区分远程服务器、本地远程跟踪引用和当前分支，避免把 `pull` 写成同步黑箱。
- 第五篇按“是否提交、是否共享”组织撤销与恢复，方向正确。
- `scripts/` 使用临时目录和本地 bare 仓库验证关键行为，没有依赖真实托管服务。
- 附录已有命令地图、场景索引、实验说明和来源页，可继续扩展为检索层。

这些内容应当保留并深化，不需要机械推倒。

## 结构问题

当前规划把“首版”定义为初学者完成日常操作，但仓库名称和用户目标要求的是覆盖个人、团队与组织治理的技术蓝皮书。`docs/BOOK-PLAN.md` 还明确把服务端管理、传输协议、子模块和大文件存储排除在主线之外，这与新范围冲突。根 README 和验收文件声称首版正文已经完成，容易让后续任务把自动检查通过误判为出版完成。

六篇结构在基础路径上连贯，到了真实工程层却突然收窄。第六篇只有约 650 行，受保护分支、发布、提交质量和排障等主题通常只有 40 至 70 行，无法承担团队策略、平台竞态、CI 证据链和故障恢复的复杂度。底层知识也分散在第一至三篇，缺少 packfile、对象生命周期、协议协商和 index 冲突阶段等承上启下的内容。

篇首页、阅读路线、规划和验收文件多次重复同一组章节概述。这些导航信息可以保留，但应由权威总纲派生，避免四处分别维护范围与完成状态。

## 技术准确性抽查

已验证的 Git 命令主线与当前实验一致，快照、引用、远程跟踪分支、非快进拒绝、三方合并和 reflog 的核心解释没有发现方向性错误。仍有几类风险需要逐章处理：

- 示例输出多为删减后的典型片段，部分章节没有明确标出“输出会随 Git 版本、哈希算法或本地配置变化”。
- `--force-with-lease` 虽有风险提示，但还要解释无参数租约与后台 `fetch` 的竞态，并提供显式期望值写法。
- 受保护分支目前把平台能力写成通用清单，没有权限、套餐、核对日期和平台差异边界。
- 发布章节正确区分源码回滚与部署回退，但缺少制品摘要、CI 身份和数据库迁移的可验证链路。
- Git 2.28+ 的基线过宽。部分新主题需要为命令和能力记录更精确的最低版本，不能沿用一个全书版本号。

## 案例与实验质量

现有实验的优点是隔离、可重复，并覆盖成功与部分失败路径。主要不足是实验说明没有全部达到统一证据契约：执行位置、前置状态、状态变化、预期输出、失败方式、恢复命令和安全边界有时分散在正文，需要读者自行拼接。

案例大多围绕 `README.md`、`app.txt`、`FIX.md` 等单文件变化，适合验证 Git 机制，却不足以代表真实工程决策。后续案例应增加多语言项目、生成文件、数据库迁移、CI 配置、二进制资产、子模块和发布制品，同时保持仓库可本地复现。真实平台行为不能用本地 bare 仓库输出冒充，应明确分为“Git 传输实验”“平台界面示例”“CI 系统示例”。

## 读者路径与出版成熟度

基础读者的前五篇路径清楚，资深工程师、Tech Lead 和 SRE 目前没有连续路径。附录能帮助检索，但缺少跨角色阅读地图、决策表、事故手册和组织策略模板。

当前文本属于结构完整的基础教程稿，尚未达到体系化市售技术书标准。主要差距不是文字润色，而是范围、证据、案例强度、跨章去重和技术审校。出版前还需要完成逐章事实核对、实验契约审计、平台事实登记、术语统一、图表规划、索引、外部技术审读和整书通读。

## 审计结论

现有内容可作为 v2 的基础层，约三分之一主题具备可复用骨架。下一阶段不应继续横向增加短章节，而要先把第三至十三篇的知识架构补齐，再按风险和依赖逐章替换。自动检查继续作为回归门禁，出版状态由 `docs/ACCEPTANCE.md` 的人工与证据门槛判定。
