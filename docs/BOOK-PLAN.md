# 《Git 技术蓝皮书》全书规划

> 实施状态：首版正文、综合场景、附录和隔离验证已完成。后续修改按本规划和 `docs/ACCEPTANCE.md` 继续审计。

## 1. 定位

这是一本文向公开读者的“教程型蓝皮书 + 工作场景手册”。它不覆盖全部 Git 命令，而是围绕开发者最常遇到的版本管理、团队协作、历史整理、回滚和恢复问题建立完整能力。

正文承担连续教学，附录和场景索引承担快速查询。读者第一次阅读时可以从头建立模型；工作中遇到问题时，也能按“当前状态 + 是否已推送”快速定位解决方案。

## 2. 目标读者

- 完全没有使用过 Git 的读者
- 只会照着流程执行 `add`、`commit`、`pull`、`push` 的读者
- 能完成日常开发，但不敢独立处理冲突、回滚和历史修改的读者

默认读者会操作终端和编辑文本文件，但不默认其掌握版本控制术语、Shell 高级语法、GitHub 工作流或 Git 内部对象。

## 3. 完成标准

读者完成全书后，应当能够：

1. 用快照、提交图、引用解释 Git 的基本工作方式。
2. 根据 `status`、`diff` 和历史信息判断当前状态。
3. 独立完成本地提交、分支开发、合并和远程协作。
4. 区分本地历史与已公开历史，选择合适的修改或回滚策略。
5. 处理常见冲突，并说明冲突双方意图与最终保留行为。
6. 找回误删分支、错误重置或失败变基前的提交。
7. 在热修复、发布分支和多人协作场景中避免覆盖他人工作。

## 4. 全书结构

### 第一篇：Git 为什么会出现

解决“为什么需要版本控制”和“Git 与前代工具有什么本质区别”。在执行命令前建立快照、历史和仓库的最小直觉。

### 第二篇：完成第一次可靠提交

引入工作区、暂存区和提交，形成最基本的观察、选择、记录闭环。

### 第三篇：用分支组织并行工作

引入提交图、引用和 `HEAD`，再进入分支、合并、冲突和标签。

### 第四篇：与远程仓库和团队协作

建立三层远程模型，再学习获取、整合、发布、变基和挑选提交。

### 第五篇：撤销、回滚与找回

按“未提交 / 已提交”和“未公开 / 已公开”组织恢复策略，是本书最重点的部分。

### 第六篇：把 Git 用进真实工程

组合已有知识处理临时切换、缺陷定位、热修复、发布、冲突说明和团队规范。

## 5. 章节类型

不再强制所有章节采用同一套八段结构，而是按内容选择以下模板。

### 概念章

问题场景 → 普通语言解释 → 工作定义 → 模型或图示 → 最小观察实验 → 常见误解 → 小结

### 操作章

任务场景 → 操作前状态 → 新命令 → 参数解释 → 可运行实验 → 结果验证 → 常见错误 → 恢复方法 → 动手试试

### 事故恢复章

事故现场 → 先保护现场 → 状态判断 → 可选方案与影响 → 推荐操作 → 验证恢复结果 → 失败时的第二恢复路径 → 事故复盘

### 场景手册章

完整需求 → 决策路径 → 分步操作 → 团队协作边界 → 验证清单 → 可复用记录模板

## 6. 练习设计

- 普通章节按需设置“动手试试”，不使用强制考试口吻。
- 每一篇设置一个综合场景，验证知识能否连起来使用。
- 高风险章节提供沙盒实验仓库，确保读者不会在真实项目中试错。
- 参考答案解释判断过程，不只给出最终命令。

## 7. 特别强化的工作场景

- 修改尚未推送的最近一次提交内容或提交说明
- 修改尚未推送的多个提交说明
- 撤销已经推送的提交，同时保留团队共享历史
- 必须改写远程历史时使用 `--force-with-lease` 并检查风险
- 误用 `reset`、删除分支、失败变基后的恢复
- 分支间迁移单个修复提交
- 冲突解决后的对外说明：冲突文件、双方意图、最终行为和验证结果
- 发布前判断服务影响、部署范围和优雅停机要求，但案例只讲 Git 决策，不暴露真实业务信息

## 8. 暂不纳入正文主线

以下内容可能进入扩展附录，但不会打断初学者主线：Git 服务端管理、复杂 hooks 开发、Git filter、replace、notes、底层传输协议、子模块的深度运维、大文件存储平台细节。
