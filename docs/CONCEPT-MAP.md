# 知识依赖图

这份文件用于防止正文突然使用读者尚未学过的知识点。写作时必须沿依赖方向引入概念。

```text
版本问题
  -> 版本控制
  -> 分布式版本控制
  -> 仓库 / 快照 / 历史 / 提交
      -> 工作区
      -> 暂存区
      -> 状态与差异
      -> 提交之间的父子关系
          -> 提交图
          -> 引用
              -> 分支
              -> HEAD
              -> 标签
                  -> 合并
                  -> 三方合并
                  -> 冲突
      -> 本地仓库与远程仓库
          -> 远程引用
          -> 远程跟踪分支
          -> fetch
              -> pull
          -> push / upstream
              -> 已公开历史
                  -> revert
                  -> force-with-lease
      -> 重新生成提交
          -> amend
          -> rebase
          -> cherry-pick
      -> 移动引用
          -> reset
          -> reflog
          -> 恢复误删或误移动
```

## 写作约束示例

- 解释 `git diff --staged` 之前，必须已经解释工作区和暂存区。
- 解释分支之前，必须已经解释提交图和引用。
- 解释合并冲突之前，必须已经解释共同祖先和三方合并。
- 解释 `git pull` 之前，必须分别解释 `fetch` 与本地整合。
- 解释 `rebase` 之前，必须说明提交不可变，以及“修改提交”实际会生成新提交。
- 解释 `--force-with-lease` 之前，必须解释远程跟踪分支和覆盖已公开历史的风险。
- 解释 `reflog` 之前，必须解释引用会移动，并区分对象仍存在与名字已经丢失。
