# 《Git 蓝皮书》权威总纲

> 状态：v2 重构基线，建立于 2026-08-20。章节增删、合并和验收以本文件为准。

## 定位与读者承诺

本书面向日常写代码的软件工程师，也面向需要制定协作规则的 Tech Lead、DevOps/SRE 和研发效能负责人。正文从个人仓库的状态判断起步，逐步进入提交图、协作协议、历史治理、平台控制面和组织级运维。读者不需要预先理解 Git，但基础内容不能以省略工程边界为代价。

全书采用两条并行路径：学习路径负责建立心智模型，事故路径负责在具体状态下找到安全动作。命令不是章节组织的中心。每个操作都要回答它在哪里执行、读取什么、改变什么、可能怎样失败、如何验证，以及失败后怎样回到已知状态。

## 全书结构

### 第一篇：版本历史解决什么问题

保留现有第一篇的主要内容，压缩版本控制代际史中的重复判断，补充可追溯性、可审查性和可恢复性三类工程目标。

- 手工副本、云盘版本与版本控制的边界
- 集中式与分布式版本控制的取舍
- Git 的诞生背景及设计约束
- 快照、差异展示与内容寻址
- 仓库、对象、引用和可达性的第一张地图

### 第二篇：建立可靠的本地工作循环

以状态观察为主线，保留现有安装、身份、初始化、暂存和提交实验。安装与配置事实要注明 Git 版本和操作系统边界。

- 安装、版本基线和帮助系统
- 身份、配置作用域与条件配置
- 仓库发现、工作区、暂存区和对象库
- `status`、`diff`、`add`、`commit`、`log`、`show`
- 忽略规则、属性文件与换行符策略
- 原子提交、提交说明和本地钩子的责任边界

### 第三篇：对象模型决定命令行为

把目前散落在第一至三篇的底层解释收束为可反复引用的模型层，避免每个命令章重新讲一次“分支是引用”。

- blob、tree、commit、tag 对象
- 对象 ID、哈希算法迁移与对象格式边界
- 引用、符号引用、`HEAD`、reflog
- 提交图、可达性、merge-base 和代际编号
- index 的数据结构、冲突阶段与稀疏索引
- packfile、delta、垃圾回收和对象生命周期
- porcelain 与 plumbing 命令的边界

### 第四篇：分支、合并与冲突

保留现有第三篇的提交图和三方合并实验，增加合并策略、重命名检测、rerere 和复杂冲突诊断。

- 分支与分离 `HEAD`
- 快进、合并提交和非快进历史
- merge-base 与三方合并
- ort 策略、冲突类型和冲突阶段
- 内容冲突、重命名/删除冲突、目录重命名
- `merge --abort`、`rerere` 与冲突复用
- 标签、发布引用与签名标签

### 第五篇：远程仓库、协议与认证

从“本地保存的远程状态”扩展到传输层和身份层。托管平台只作为控制面实例，不把某一家平台的按钮当成 Git 语义。

- remote、refspec、远程跟踪分支
- clone、fetch、push、pull 的状态变化
- fetch/push 协商、浅克隆、部分克隆和过滤器
- HTTPS、SSH、凭据助手、令牌和 SSH agent
- 主机密钥校验、证书与企业代理
- 非快进拒绝、原子推送和 push options
- GitHub、GitLab、Bitbucket 等平台的厂商无关抽象

### 第六篇：共享历史的协作与评审

将现有代码评审准备、提交质量和保护分支内容合并为完整协作系统。

- 主干开发、功能分支、发布分支和维护分支
- 合并请求/拉取请求的共同模型
- merge、squash、rebase merge 的历史后果
- 评审范围、变更堆叠、草稿评审与所有权
- 必需检查、审批、CODEOWNERS 类规则与绕过治理
- 合并队列、竞态和过期审批
- CI 身份、状态回报和失败分类
- 团队约定如何转化为平台策略与审计证据

### 第七篇：改写、撤销与恢复

保留现有第五篇的状态矩阵，把每个动作放进“是否共享、是否可恢复、恢复窗口多长”的决策框架。

- restore、unstage 与工作区保护
- amend 与交互式 rebase
- cherry-pick、revert、reset 的语义差异
- `--force-with-lease`、显式租约与后台 fetch 竞态
- reflog、ORIG_HEAD、rebase 状态目录和恢复引用
- 误删分支、错误 reset、失败 rebase、错误强推
- 已过 reflog/GC 窗口后的对象取证
- 远端、备份和同事克隆作为恢复来源

### 第八篇：发布与 CI/CD 集成

Git 只证明源码历史，不能替代构建、制品、配置、数据库和运行环境证据。

- 提交触发、分支触发、标签触发和路径过滤
- 候选提交、临时合并、squash/rebase 结果与合并队列的对象绑定
- 可重复构建、制品摘要与源码提交关联
- 构建输入闭包、非确定性来源、构建清单和构建一次提升同一制品
- 发布 tag、版本命名、候选发布、审批记录、制品提升和同名引用竞态
- 发布标签、候选版本和版本号策略
- 部署回退与源码回滚的区别
- rollout 状态、金丝雀/蓝绿/滚动部署、实例实际 digest 与旧实例围栏
- 数据库迁移、向前兼容和不可逆发布
- expand/contract、可续跑回填、锁与事务边界、schema/data 兼容矩阵
- 长任务、异步消息和混合版本窗口的回退边界
- 事故证据冻结、缓解与修复状态机
- `bisect` 候选、hotfix/cherry-pick 来源与目标提交、共享依赖的部署范围
- 从运行基线到制品、rollout、业务验证、关闭条件和复盘行动项
- CI 中的浅克隆、分离 `HEAD`、凭据和权限
- merge queue 与通过后变红的竞态
- 从事故到修复、发布、回滚和复盘的证据链

### 第九篇：大仓库、二进制与仓库组合

覆盖小型源码仓库之外的容量和拓扑决策。

- 性能测量：命令时延、对象规模、引用规模和工作区规模
- commit-graph、multi-pack-index、bitmap 与维护任务
- 稀疏检出、稀疏索引、部分克隆和 scalar 类工作流
- refspec、shallow、partial、sparse 四层限制的组合和恢复
- monorepo 的边界、构建图和所有权
- 变更闭包、路径过滤、共享库原子变更和跨团队审批
- monorepo 拆分/合并、OID 映射、发布单元和恢复责任
- 二进制文件、Git LFS 的指针模型、锁定和配额
- 子模块的 gitlink 模型、递归操作和供应链风险
- subtree 的历史复制模型与同步成本
- 多仓库、子模块、subtree、monorepo 的决策矩阵

### 第十篇：安全、签名与供应链

安全内容不附着在某一家托管平台上，分别讨论 Git 对象、传输、身份、策略和制品。

- 凭据不进入历史，泄漏后的轮换与历史清理
- 最小权限令牌、部署密钥、机器人身份和短期凭据
- commit/tag 签名、SSH/GPG/S/MIME 选择与验证策略
- 签名证明什么，不证明什么
- 受保护引用、权限分层、审批和不可抵赖审计
- hooks、CI 配置、依赖锁文件和第三方 action 的供应链风险
- 不受信任仓库、`safe.directory`、配置和过滤器边界
- 秘密扫描、恶意对象与归档导出风险

### 第十一篇：取证、迁移与灾难恢复

恢复章节必须区分逻辑误操作、对象丢失、服务不可用和合规调查。

- 事故现场保护与只读证据采集
- reflog、fsck、lost-found、pack 与替代对象库
- 历史归因：log、blame、pickaxe、pathspec 与 rename detection
- bundle、mirror、备份与恢复演练
- SVN/其他 Git 服务向 Git 的迁移
- 作者映射、标签、LFS、issue/评审数据和权限迁移
- 历史重写、敏感信息清理与协作者重新克隆
- 仓库损坏、远端丢失和区域故障的恢复预案

### 第十二篇：组织级运维与治理

把仓库当作有生命周期的工程资产，而不是只供开发者推送代码的目录。

- 仓库创建、归档、转移和删除流程
- 默认分支、命名、保留和所有权策略
- 权限模型、离职回收、机器人账户和紧急访问
- 分支保护、规则集和例外审批
- 审计日志、合规留存与证据导出
- 仓库健康指标、容量预算和维护窗口
- 服务端 hooks、策略即代码与渐进治理
- 组织级故障手册和恢复演练

### 第十三篇：故障排查手册

按症状和证据组织，不按命令字母排序。

- “文件不见了”与“提交不见了”
- 工作区无法切换、合并或 rebase
- push 被拒绝、认证失败和权限不足
- 远程引用过期、默认分支变更和删除引用残留
- 仓库过慢、对象库膨胀和磁盘耗尽
- LFS 对象缺失、子模块无法检出和 CI clone 异常
- 签名无法验证与密钥过期
- 仓库损坏、锁文件残留和并发操作
- 求助时应提供的最小证据集

## 内容依赖与阅读路径

基础读者按第一、二、三、四、五、七篇阅读，之后选择协作或发布路径。团队负责人可从第三篇复核模型，再读第六、八、十、十二篇。DevOps/SRE 重点阅读第五、八、九、十、十一、十三篇。事故现场优先使用场景索引，不要求顺序阅读。

每篇都要给出进入条件和退出能力。跨篇引用指向一个权威解释，后续章节只补当前场景的差异，避免重复定义。

## 版本与厂商事实规则

Git 核心语义优先引用 `git-scm.com/docs`、Git 源码仓库的 `Documentation/` 和可复现实验。平台功能必须标注厂商、产品层级、权限前提和核对日期；计费、套餐、界面位置和默认策略不得写成永久事实。正文优先使用“托管平台的合并请求”“必需检查”“受保护引用”等抽象，再用 GitHub、GitLab 或其他平台作带日期的实例。
