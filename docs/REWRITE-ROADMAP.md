# v2 改写路线

## 工作原则

每一阶段都要同时更新正文、实验、来源、进度和验收证据。正文新增命令时，实验或明确的不可本地验证说明要在同一阶段补上。平台事实写入 `docs/FACT-REGISTER.md`，标明厂商、产品层级、权限、计费影响、核对日期和来源。

## 阶段 0：建立基线

状态：已完成（2026-08-20）。

- 完成仓库审计、权威总纲、质量标准和进度文件。
- 修正“首版已完成”的状态表述。
- 保留现有 79 页和 8 组实验作为回归基线。
- 建立章节清单，标记保留、合并、扩写、新增和删除候选。

退出条件：范围文件之间不再冲突，任何后续任务都能从总纲和进度文件恢复上下文。

## 阶段 1：统一核心模型与实验契约

- 重构第一至三篇，形成快照、对象、引用、index、可达性和对象生命周期的统一模型。
- 给现有命令实验补齐七项信息：前置条件、执行位置、命令、状态变化、预期输出、失败方式、恢复办法。
- 统一示例仓库、分支名、Git 版本记录和输出省略标记。
- 把跨章重复定义改为权威章节加链接。

退出条件：后续章节可以只引用模型，不再重新定义对象、引用、`HEAD` 和远程跟踪分支。

## 阶段 2：完成协作、评审与历史治理

- 深化分支、合并、复杂冲突、rebase、cherry-pick、revert 和 reset。
- 新写平台厂商无关模型、评审状态机、合并策略、必需检查和合并队列。
- 扩充强推竞态、公开历史修复和多人恢复案例。
- 用本地 Git 实验验证对象与引用变化，用带日期的平台资料验证控制面行为。

退出条件：个人开发者和团队能从同一提交图推导协作动作，平台设置与 Git 核心语义没有混写。

## 阶段 3：远程、认证、安全与供应链

- 补齐协议 v2、refspec、浅克隆、部分克隆、HTTPS/SSH 和凭据助手。
- 新写令牌、部署密钥、机器人身份、签名、受保护引用和审计。
- 建立秘密泄漏、密钥轮换、历史清理和重新克隆的完整事故实验。
- 审查示例中的不受信任配置、hooks、过滤器和第三方 CI 依赖。

退出条件：读者能区分认证、授权、完整性、来源证明和审计留痕，安全结论都有边界。

## 阶段 4：CI/CD、发布和运行证据

- 新写 CI clone 语义、分离 `HEAD`、凭据权限、缓存和状态回报。
- 把源码提交、构建过程、制品摘要、部署记录和运行版本串成证据链。
- 增加合并队列、路径过滤、标签触发、数据库迁移和不可逆发布案例。
- 扩写发布回退与源码回滚的组合决策。

退出条件：所有发布案例分别验证 Git 状态、构建制品和运行状态，不用提交历史替代部署证据。

## 阶段 5：规模、二进制和仓库拓扑

- 增加仓库性能测量与维护实验。
- 新写 commit-graph、MIDX、bitmap、稀疏检出、部分克隆和后台维护。
- 新写 LFS、子模块和 subtree 的机制、失败路径与迁移。
- 给 monorepo、多仓库、子模块和 subtree 建立决策矩阵。

退出条件：每项优化先有测量口径，拓扑建议说明规模、权限、构建和运维代价。

## 阶段 6：迁移、取证、灾难恢复和组织治理

- 新写 bundle、mirror、备份验证、对象库损坏和区域故障演练。
- 完成 SVN/托管平台迁移，覆盖身份、标签、LFS、评审数据和权限。
- 扩展历史调查工具和证据保全流程。
- 新写仓库生命周期、权限回收、审计留存、容量预算和策略例外。

退出条件：恢复目标、恢复点、恢复时间和证据保留要求都有可执行方案。

## 阶段 7：整书工程与出版审校

- 全书跨章去重，统一术语、图例、命令格式和案例角色。
- 运行全部自动实验并人工复核高风险章节。
- 完成平台事实复核、外部链接检查和来源分级。
- 邀请基础读者、资深工程师和 Git/DevOps 专业审读分别试读。
- 完成索引、图表、版权、匿名化和最终版式检查。

退出条件：`docs/ACCEPTANCE.md` 的出版门槛全部有证据，不存在以“脚本通过”代替内容审校的项目。

## 每章改写循环

1. 读取整章及前后依赖，记录保留内容和重复内容。
2. 列出事实断言、命令、平台能力和风险动作。
3. 先补模型与决策，再补命令和案例。
4. 为实验写明七项契约，并在隔离环境运行。
5. 核对官方来源和版本边界。
6. 运行链接、实验、标点和 diff 门禁。
7. 更新 `docs/PROGRESS.md`，记录完成证据和遗留问题。
